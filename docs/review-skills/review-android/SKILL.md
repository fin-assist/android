# review-android

1. Проследи изменённый пользовательский сценарий через UI state, ViewModel, repository и API/mock. Проверь, что правила домена и форматирование остаются в своих слоях и фейк соблюдает контракт.
2. Проверь loading/empty/error, повторное нажатие, возврат, отмену, повтор запроса, смену конфигурации и восстановление процесса, если состояние должно сохраняться. Старые готовые данные и идентичность запроса не должны незаметно теряться.
3. Проверь неизвестные коды/поля, валюты и исходный пояс данных; вычисления mock сверяй с contracts. Проверь изоляцию учётных записей и очистку кэша при выходе/удалении.
4. Для изменённого UI найди проверку дизайна и сценарий Maestro/native, Qase mapping и docs/e2e.md либо конкретную причину отсутствия. Чтение/авторство теста не является его прогоном. UI-тесты не запускай без отдельного разрешения владельца.
5. Проверь секреты/Keystore, сеть, экспортируемые компоненты и исключение mock/e2e hooks из production. В итоге приведи путь сценария и тест, который обнаружит его нарушение.

Результат — проверяемые наблюдения в рамках Code Review Rules. Сам навык не разрешает внешние действия.
