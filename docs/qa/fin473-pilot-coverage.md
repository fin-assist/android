# FIN-473: границы пилота Qase82/83/89

Согласовано владельцем 08.11.2026: сократить дорогие сквозные цепочки, сохранив покрытие
проверками на подходящем уровне. Исходный текст кейсов и ранее выполненные результаты
сохраняются в `qase-parity/finance.json`; этот документ не переписывает историю.

Каждый из трёх кейсов теперь имеет два обязательных компонента в существующем
`scripts/qase-cases.json`: Maestro journey и метод `AnalyticsReliabilityComponentTest`.
Отсутствие, пропуск или отказ любого компонента не даёт полного Passed. JVM-компоненты
исполняются как обычные Compose/Robolectric tests на PR и отдельно собираются на main
в артефакт `e2e-components` для общего UI/Qase verdict. Результат JVM не является
результатом исполнения Maestro и наоборот.

Компонентные тесты рисуют настоящий `AnalyticsContent`, подключённый к настоящему
`AnalyticsViewModel`. API — управляемый fake объявленного интерфейса; задержанные ответы
удерживаются `CompletableDeferred`, polling и `ElapsedClock` используют один
`TestCoroutineScheduler`. Не используется Android control Activity или реальные sleeps.
State injection не выдаётся за проверку ViewModel: переходы выполняет реальный ViewModel.

Mapped JVM method: `qase89UnknownReadRecoveryAndDeferredSelection`. В трёх независимых
компонентных фазах суммарно ровно3 PUT: по одному на сценарий, recovery не добавляет PUT.

сквозным в Qase83 и тестах истории/удаления. Сетевой транспорт и сервер не проверяются fake API.

## Проверка исполнения

Команда для JVM companions:

```bash
./gradlew :feature:analytics:impl:testDebugUnitTest --tests '*AnalyticsReliabilityComponentTest'
```

Команда исполняется с внешним реальным process deadline; состояние и результаты исполнения
фиксируются в PR/FIN-473. До успешного исполнения новых companions и изменённых journeys
пилот не считается принятым. Автоматические emulator UI на PR не включаются.
